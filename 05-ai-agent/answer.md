### 1.2 任务判断

**材料与 Gold 的关系**：Gold 是对材料的正确聚合，但**不是"可重算"的典范**。`gold/expected_answer.xlsx` 共 6 个工作表、39 行原值追溯，**公式数量为 0，全部为静态值**（openpyxl 扫描 `data_only=False` 结构，无任何 `=` 开头单元格）。而 `instruction.md:5` 要求"must all be recalculable and traceable to the ledger"。Gold 满足 traceable（`原值追溯!K:L` 有来源表与坐标），但**不满足 recalculable**。

**主要难度来源**：**业务归因，而非文件解析**。理由：

1. 材料是干净的结构化台账，两表同构、列序稳定、无合并单元格、无缺失编码；唯一解析摩擦是源表同比列有 5 处浮点尾巴（如 `0.08333333333333326`）和 3 类"空"（新开/关闭的同比列为 `None`），这两点不影响核心链。
2. 真正的难点在三处业务判定：(a) 状态是**期间相对**的——湖滨店在 2023→2024 是"新开"、在 2024→2025 是"持续经营"，西苑店反之转为"关闭"；(b) 六条链必须共用**同一个分母**（品牌净变化 +48/+59），不能用持续经营影响、餐段自身同比或上期总量；(c) 状态维度与餐段维度是**正交**的，两个 100% 不可相加。
3. **评分环节的摩擦却主要来自非业务因素**——见第 2、4 节：同一份内容正确的答案，仅因"期间写成 `2023→2024` 还是 `2023年→2024年`、闭合检查写成独立表还是列在核验清单里"，得分在 0.29～1.00 之间摆动。

**最重要的 3 个设计问题与最小修复**：

| # | 问题 | 证据 | 最小修复 |

### 4.5 结构差异容忍、解析失败、普通遗漏与重复表现的统一处理

1. **结构差异容忍**：以"逻辑键（期间, 门店, 餐段）+ 角色（原值 / 绝对影响 / 分母 / 带符号贡献 / 状态）"绑定，不绑定 sheet 名、列名、行列方向。宽表与长表等价：长表多出的"影响类别"维度作为**可选身份字段**处理，缺省时按"该期间-餐段唯一一行"识别；出现多行时优先取"合计/小计"角色行，其次取三类分解的算术和。列名走同义词表（如 `餐段净影响`＝`绝对影响`、`餐段签署贡献率`＝`带符号贡献`、`左侧值/左值`＝`左值`），同义词表未命中时进入一次语义复核，**复核结果写回同义词表**形成积累。
2. **解析失败**：必须区分三种状态——`已绑定且正确` / `已绑定但值错` / `未验证（绑定失败）`。第三种记 0 但打 `unverified` 标记，**不得等同于"内容缺失"**，且不得触发整份工作簿判错（对齐 rubric:8 与 `program_judge.py:90` 的冲突）。同一工作簿若 `unverified` 叶子超过 40%，转人工整体复核，而不是直接给低分。
3. **普通遗漏**：按叶子比例扣（`n/N`），不做 `min` 聚合，不乘 0.8 折扣。遗漏与错误同权，但遗漏不触发 X 系列扣分。
4. **同一根因的重复表现**：每个错误分配 `root_cause_id ∈ {denominator, status_period, double_count, unit, transcription, omission, parse}`。同一 `root_cause_id` 在多个维度出现时**只扣一次**（取该根因下最重的维度扣分），其余维度只做"标记不计分"。`control:repeated_same_error` 与 `control:single_error` 应同分（现有实现已做到 0.82/0.82，这点值得保留），而 `two_independent_errors` 应显著低于两者（现有 0.61，方向正确但绝对水平偏高——按新表应 ≈0.45）。
5. **解析失败与内容错误的分离**：解析失败只影响"能否验证"，不影响"是否正确"；当同一逻辑键在另一份表里可验证时，以可验证者为准，冲突则记录 `key_conflict` 并降权而非清零（修正 `program_judge.py:120-126`）。
